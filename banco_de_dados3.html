Modelagem de dados

O que é modelagem de Banco de Dados??

Processo de representar a estrutura lógica de um sistema de informação, criando um mapa visual de como os dados serão armazenados, organizados e relacionados. Basicamente, criar uma planta baixa para a estrutura do banco de dados.


  • Características de uma boa modelagem de Banco de Dados:
    1. Integridade:Dados corretos e consistentes (sem duplicações ou referências quebradas).
    2. Performance: Estrutura bem modelada, permite consultas rápidas e operações eficientes.
    3. Manutennbilidade: Facilita futuras modificações e expansões do sistema sem quebrar funcionalidades.

    Porque modelar antes de programar?

    Evita retrabalho, mais comunicação clara, consistência e qualidade.


    Modelo Conceitual de dados

    O que é?

    Desenho simples que mostra como as informações se organizam. Mostra o que guardar e não como.

  • Conceitos fundamentais do modelo conceitual:
    1. Entidade:

      • Coisas importantes do sistema.
      • Exemplos: Clientes, produtos, pedidos...

    2. Atributo:
      • Características de cada entidade.
      • Exemplo: Produto (entidade) contém: Nome, Preço, ID.

    3. Relacionamento:
      • Como as entidades se conectam
      • Exemplo:
        1. Cliente faz pedido.
        2. Pedido contém produto.

    4. Cardinalidade:
      • Define quantas instâncias de uma entidade se relacionam com outras.
      • Exemplo:
        • Um cliente pode fazer muitos pedidos (1:N).
        • Porém, um pedido não pode ter vários clientes.

    Modelo Entidade-Relacionamento (ER)

    O que é?

    Desenvolvido por Petter Chen (1976), visual, intuitivo e universalmente reconhecido na área de dados.

  • Representações gráficas:
    • Entidade: Retângulo.
      • Pensar como se fosse uma classe no Java!
    • Atributo: Elipse.
      • Pensar como se atributos fossem variáveis de uma classe em Java!
    • Relacionamento: Losango.
      • Pensar como se um relacionamento fosse um método ou uma referência ao objeto que conceta duas classes!

  • Tipos de atributos:
    • Atributo Simples (Atômico): Não pode ser dividido em partes menores, como "CPF" ou "Idade".

    • Atributo Composto: Pode ser subdividido em componentes menores que possuem significado próprio, ex: "Endereço" dividido em "Rua", "Número", "Bairro" e "CEP".

    • Atributo Monovalorado: Assume apenas um valor para uma determinada entidade, ex: "Data de Nascimento".

    • Atributo Multivalorado: Pode assumir múltiplos valores para uma única entidade, representado com elipse dupla, ex: "Telefones" de um cliente ou "Dependentes".

    • Atributo Derivado: Seu valor é calculado ou obtido a partir de outro atributo, ex: "Idade" (derivado da "Data de Nascimento").

    • Atributo Determinante (ou Chave/Primário): Identifica de forma única cada entidade no banco de dados, ex: "CPF" ou "ID_Funcionario".

    Modelo Lógico

    O que é?

    Traduz o modelo conceitual para a estrutura do SGBD.


  • Definições:
    • Tabelas e seus nomes definitivos.
    • Colunas com tipos de dados.
    • Chaves primárias e estrangeiras.
    • Relacionamentos implementada através de FK's.
    • Regras de negócio básicas.

    PK - Primary Key (Chave Primária)

    • É o identificador único de uma tabela.
    • Não se repete.
    • Não pode ser nulo.

    FK - Foregin Key (Chave Estrangeira)

    • Campo que faz ligação com a PK de outra tabela.
    • Pode repetir.
    • Cria o relacionamento entre tabelas.

    Modelo Físico

    O que é?

    É quando o Banco de Dados é criado de verdade no computador.


    • Índice: Servem para encontrar dados mais rápido.
    • Particionamento: Divide tabelas muito grades em partes menores.
    • Regras (Contraints): Garante que os dados estejam corretos.
    • Cardinalidade: Um registro se relaciona com outro.
